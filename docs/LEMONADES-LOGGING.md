# 9R 启动与故障日志

更新：2026-10-26。以下能力已在源码实现并做离线验证；没有连接或刷写一加 9R。

## 已有与本轮补齐

| 能力 | 实现及边界 |
| --- | --- |
| UEFI 启动日志 | 保留最初 8 KiB 和最新 24 KiB；超过容量时按时间顺序导出，插入中间内容丢失标记。原先 32 KiB 满后停止记录，会漏掉最后的错误。 |
| USB 回复格式化 | 与日志缓冲分离；日志写满后，`result`、屏幕尺寸等回复仍可正常生成，不会修改或覆盖日志。 |
| 故障返回日志 | 原有内核日志及 early-exception 的 ESR/ELR/FAR/LR/SP 记录保留。本轮修复返回后的重复 `oem log` 清掉已保存内核日志的问题；切换截图导出后仍能重新导出故障快照。 |
| 电脑端日志采集 | 新增 `tools/lemonades/collect_loader_logs.py`，只连接已经运行的 `xnuloader` / `lemonades`；不自动启动加载器。 |
| 连续采集与证据 | 指定次数、间隔和命令超时；每次导出前后检查产品/平台。保存原始字节、UTF-8 便读副本、时间、状态、命令结果和 SHA-256。错误、超时、断线或 Ctrl-C 保留已采集文件及清单。 |

加载器版本改为 **0.6**，这是 xnuloader 工具版本，不是 iOS 版本。
新增 `getvar log-format`（`head-tail-v1`）及 `getvar log-dropped`（本次 UEFI 日志丢弃的字节数）。
内核自身已有独立的头部/尾部环形日志；UEFI 的丢弃计数不代表内核丢弃计数。

内核返回快照保存在加载器 `out_buf` 中，不依赖返回后仍有效的内核指针。
在开始新一次运行或重新组合日志时，该快照会被替换；它不是跨重启日志存储。
保留故障快照期间 `oem log` 取得的是返回时的快照，不包含此后额外打印的 UEFI 诊断。

## 使用

前提：手机已通过另行验证的流程运行本项目 9R 加载器，而且 Qualcomm USB 协议可用。
普通 Android bootloader 即使有 fastboot 连接，也不满足这个条件。
本工具不会帮手机进入该状态；**当前 9R probe 仍禁止 XNU handoff**。

在仓库根目录运行，将 `实际序列号` 换成该手机当前 fastboot USB 序列号：

```sh
python3 tools/lemonades/collect_loader_logs.py \
  --serial 实际序列号 \
  --output out/lemonades/device-logs/session-001 \
  --count 30 --interval 2 --timeout 10 \
  --loader-image out/lemonades/loader.efi
```

输出目录必须是新的。`--count 1` 只抓一次；最多 1000 次，每次接受的日志最大 2 MiB。
间隔指上一次采集结束至下一次开始的等待时间，不是精确采样周期。
`--loader-image` 可省略；它只记录电脑端参考镜像的哈希，不能证明手机实际运行了该镜像。
不要同时运行其他 fastboot/`xl` 客户端：加载器的 USB staging 缓冲是共享的。

目录包含：

- `0000.bin` 等：未去除 NUL、未重新编码的原始日志。
- `0000.txt` 等：便读副本；非法 UTF-8 会替换，分析原始证据使用 `.bin`。
- `*.partial.bin`：失败或未通过检查的传输，不能作为成功采集使用。
- `manifest.json`：每次采集身份检查、命令输出、返回状态、文件哈希及是否中断。

返回码 `0` 只表示请求的日志快照已采集，`1` 表示失败，`130` 表示 Ctrl-C 中断。
同一个序列号/平台检查不能证明两次传输之间没有重启。
运行中快照没有内核日志写锁，不能声称它是原子的或没有漏字节。
不要把重复快照直接拼接成时间线：快照可能重叠、丢失中间内容或属于不同启动。

发送到手机的命令只有 `getvar`、`oem log`、`get_staged`。`oem log` 会重新组织手机 RAM
中的 staging 缓冲，因此“只读”指不改手机持久化存储、不切换启动状态；不是完全不写 RAM。
旧的 `xl log` 会调用 `enter()`，可能重启 Android 或 `fastboot boot` 加载器，不等同于本工具。

## 尚不能保证

- **复位、断电后取回日志**：没有验证 9R 跨重启保留 RAM 区及 Recovery 读取链路；手机断电会失去当前 RAM 日志。
- **写入手机日志分区**：9R 的原始 `logdump` 分区写入仍关闭，没有借用其他机型分区。
- **USB 初始化前的死机**：电脑采集依赖可工作的 USB 命令循环；更早的故障需要已验证的屏幕输出、UART 或独立持久化记录路径。
- **硬件串口**：9R UART 焊点、电平、复用及固件使能尚未实测，不能直接给出接线结论。
- **iOS 全系统日志**：原厂 logd 的完整持久化、应用 crash report/sysdiagnose 和桌面诊断链路不由本工具补齐。

## 验证

证据在 `out/lemonades/logging-verification/verification.json`。

- 137 项主机测试通过（本轮新增 12 项）；实际环形缓冲和实际日志组合函数经 ASan/UBSan
  测试，覆盖容量边界、多次回绕、二进制数据、截断、重复导出和格式化边界。
- 模拟 fastboot 子进程覆盖错设备、传输后身份变化、返回码为零但协议失败、超时、断线、
  空/超大日志、Ctrl-C，以及不覆盖既有目录；没有调用真实手机。
- lemonades probe 和默认加载器均构建通过；保留已有 `IMAGE` 未使用编译警告。
- 通用 QEMU 的 probe UEFI 启动通过，输出 42 项协议存在性记录；不等于 Qualcomm USB 实机通过。
- 同一最小 XNU 内核的静态 Mach/BSD 用户态回归通过，无非预期 panic。没有修改内核源码，
  没有重建手机固件 FD 或刷机镜像；旧 FD 不会自动包含本轮新版加载器。
